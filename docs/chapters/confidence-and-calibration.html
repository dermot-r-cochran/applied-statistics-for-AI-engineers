Confidence and calibration

A trustworthy score is not just discriminative. It should also mean roughly what it says across the slices that matter.

Core idea

In Project Frog, a confidence score of 0.8 should imply that roughly eight out of ten comparable cases are genuinely high risk. If the observed rate is much lower, the model is overconfident; if much higher, it is underconfident.

The same habit applies to top-line metrics. A smaller test set should usually lead to a wider uncertainty interval, not the same level of confidence in the point estimate. Observed accuracy should be reported with an interval and assumptions, not treated as a fixed property of the system.

Why engineers care

Thresholds, queue sizes, human workload, and automated fallbacks all assume the score maps cleanly to real outcomes.

How it fails

Shifted data, selective labeling, class imbalance, and score clipping can all make apparent confidence unreliable.

What to check

Inspect bins, compare slices, track expected versus observed frequency, and review failure cases around operating thresholds.

Worked example: same observed accuracy, different stability

Synthetic evaluation set Observed accuracy 95% Wilson interval Why it differs
Project Frog field trial A: 890 correct out of 1,000 sightings 89% 86.9% to 90.8% More rows make the uncertainty band narrower under the same independence assumption.
Project Frog field trial B: 89 correct out of 100 sightings 89% 81.4% to 93.8% Fewer rows mean the point estimate is less stable, so the interval should widen.

The point estimate is identical in both fictional trials. The interval width changes because sample size changes.

Questions to ask before trusting a score

  • Does calibration hold for each important habitat or season?
  • Is the threshold chosen for a real operational trade-off?
  • Are abstentions or missing labels distorting the observed outcome rate?
  • Is score behavior stable between the current test set and the intended deployment conditions?
  • Are repeated rows, shared collection sessions, or clustered habitats making row-count-based intervals too narrow?
